Campus Lost & Found

AI-assisted campus lost-and-found proof of concept with auto-tagging and explainable top-3 matching.

Canonical document: devpost/scope.md (Status: Approved)

💡 The Unique Kernel

Auto-Tagging + Explainable Transparent Matching: A lightweight Flask CV microservice (YOLOv8 + OpenCV) auto-detects category and color from uploaded photos. The app is built manual-first with dropdowns always visible; unrecognized items gracefully default to "other" for manual selection. Top-3 matches expose human-readable reasons ("Same category, same color, 2 shared keywords, close date") so students immediately trust the result.

🎯 Proof of Concept Boundaries

  • React + Tailwind Frontend with Route Guards
    Responsive feed with filters (Lost/Found, Category, Status), image upload preview, redesigned two-column detail view with Top Likely Matches, and protected route navigation.
  • User Accounts, JWT Auth & Item Ownership
    Secure registration and login using bcrypt password hashing, 7-day JWTs, and owner-only return authorization (403 for non-owners).
  • Interactive Navbar Notification Center
    Dual delivery modes: public campus upload broadcasts before login, and targeted private candidate match alerts for owners after login. Badge count decrements strictly on "Mark as returned".
  • Private Ownership Challenge & Protected Contact Reveal
    Found items support private verification questions with hashed answers, 3-attempt limits, and 5-minute lockouts. Contact info is strictly excluded from public feeds.
  • Manual-First Dropdowns with Editable Tags
    Category and color dropdowns are always visible. Supports standard campus items and audio gear (earbuds, airphones, headphones). Unrecognized items default to "other"; users can freely override any tag.
  • Node/Express + MongoDB API with Explainable Matcher
    CRUD endpoints, 41 automated tests, seed script (2 demo users, 9 items), and deterministic 100-point matching with plain-language reason chips.
  • Flask Computer Vision Microservice
    YOLOv8 category inference + OpenCV HSV dominant color extraction; integrates via Express proxy with automatic 3s timeout fallback.
  • Local Run Baseline + Docker Compose Multi-Container Stack
    Clean local process startup instructions (npm/python) as the reliable baseline, with Docker Compose orchestration for full stack deployment.
  • No Password Reset / Email Verification
    User accounts rely on local email/password registration with bcrypt without third-party email confirmation or password recovery workflows.
  • Lost Item Direct Contact Reveal
    While found items can require private ownership challenge answers, lost items reveal contact to any authenticated user to expedite owner notification.
  • In-App Only Notifications
    Notifications are housed exclusively inside the navbar notification center (broadcasts for guests and targeted matches for owners); external SMS/push gateways are omitted.
  • Interactive Campus Map
    Pinpoint exact building or campus spot via Leaflet/Google Maps.
  • External Push & SMS Gateways
    Direct phone SMS or push alerts triggered when high-scoring matches arrive.
  • Multimodal Semantic Embeddings
    Vector embeddings (e.g. CLIP) for fuzzy visual and semantic text similarity.
  • Campus Admin & Security Portal
    Dedicated dashboard for lost property custody desks with audit logging.
  • Third-Party Email Verification & Password Reset
    Why cut: Avoids external SMTP/SendGrid service dependencies, keeping the application fully self-contained and reproducible.
  • In-App Chat / Messaging
    Why cut: WebSockets and chat history add complex infrastructure; direct student contact (email/phone) works immediately offline.
  • Native Mobile Application
    Why cut: High build overhead and distribution friction; responsive web fits every campus device without app store approvals.
  • Complex Multi-Stage Claim Arbitration
    Why cut: Challenge question verification paired with physical confirmation resolves ownership cleanly without administrative bureaucracy.

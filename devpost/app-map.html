Application Architecture

Campus Lost & Found is built as a modular multi-service system designed to keep student data private and the user interface responsive even if machine learning services lag or fail:

1
Client Photo Upload (Browser) User selects photo on Report page → instant preview rendered client-side via object URL.
2
In-Memory Express Tag Proxy Express validates 5MB limit in memory and streams file buffer to Flask with 4s abort timeout.
3
Computer Vision Inference (Flask Microservice) YOLOv8 nano identifies object category → OpenCV extracts HSV bounding box pixels for dominant color.
4
Auto-Tagging with Manual Control Category and color auto-fill with "Suggested automatically" chip; student can edit dropdowns freely.
5
Explainable Deterministic Matching Express queries opposite-side active items → scores candidates out of 100 → generates human-readable reason chips.

Guided Code Tour Route (3 Key Stops)

Follow how a single photo selection journeys through the entire codebase:

Stop 1: The Resilient Proxy Boundary
backend/src/routes/detect.js • router.post('/')
Notice how multer uses memoryStorage() to ensure no unverified files ever hit the disk during tag previews. If Flask times out or fails, Express catches the abort error and immediately returns { category: 'other', color: null, fallback: true } with HTTP 200, guaranteeing the browser never freezes.
Stop 2: YOLOv8 Detection & HSV Majority-Vote Color Extraction
cv-service/detector.py • ItemDetector.detect() & cv-service/color.py
YOLOv8 runs CPU inference and maps COCO class labels to campus categories (e.g. backpack → bag). It crops the bounding box (or takes a 50% center fallback) and passes it to color.py, which counts HSV pixels across the 8 core campus colors using majority vote.
Stop 3: Deterministic Scoring & Reason Generation
backend/src/services/matcher.js • calculateMatch()
Instead of opaque neural embeddings, the matcher computes a transparent 100-point score across 5 factors (Category 40, Color 25, Keywords 15, Location 10, Date 10). It strictly enforces the PRD qualification rule (Same category OR ≥2 factors, score ≥25) and generates exact chips like "2 shared keywords: straps, zip".

To Change This, Start Here

Add a New Category

cv-service/detector.py

Add the COCO label to LABEL_TO_CATEGORY, update CATEGORIES in Item.js, and add the option to ReportPage.jsx.

Tune Match Thresholds

backend/src/services/matcher.js

Adjust point weights in calculateMatch() or qualitative tier boundaries (Strong ≥70, Good 55–69, Possible 25–54).

Modify Contact Privacy

backend/src/routes/items.js

Review .select('-contact') in feed/detail queries and the dedicated /reveal-contact endpoint.

Add Stopwords

backend/src/services/matcher.js

Update LOCATION_STOPWORDS or standard English stopwords in the tokenization filters.

A Practice to Reuse: Plan-First Boundary Definition

In traditional hackathon coding, developers often rush into building a direct client-to-AI integration or jump straight to vector databases, leading to fragile architectures, opaque matches, and deployment blockers.

The Core Takeaway

By taking the time in spec.md to specify an Express proxy buffer with offline fallback and a deterministic scoring table before writing code, we made the entire product testable and resilient. When Flask was offline, the app never crashed; when keywords matched, tests proved the exact score. On your next project with an AI coding agent, always specify the boundary failure modes and mathematical rules before writing implementation code.

🗺️ End-to-End Product Journey

Follow the user through arrival, posting, background CV assistance, top-3 explainable matching, and item resolution:

🖥️ Screen & Behavior Specifications

Layout & Navigation

  • Header: "Campus Lost & Found" + dual action buttons ("I lost something" and "I found something").
  • Filter Row: Type (All/Lost/Found), Category (All, bag, bottle, phone, umbrella, laptop, book, other), Status (Active/Returned).
  • Responsive Grid: 1 column on mobile, 2–3 columns on desktop, newest first.

Card Information Architecture

  • Consistent 4:3 aspect ratio photo thumbnail.
  • Lost or Found badges with explicit text labels.
  • Category and color pills (e.g., bag blue).
  • Short description (truncated 1–2 lines), location, and date.
  • Privacy guard: Contact info completely omitted from feed payloads and card UI.

Form Fields & Validation

  • Photo input (Required): Images only (JPG/PNG/WebP), max ~5MB. Clear inline error if missing or too large. Instant preview.
  • Required Dropdowns: Category and Color dropdowns are always visible and editable.
  • Description: Free text with hint: "Add details that aren’t obvious from the photo..."
  • Location & Date: Location input + date picker (defaults to today).
  • Contact: Phone or email (required). Privacy notice: "Contact info is hidden from the feed and shown only when someone clicks Contact the poster."
  • Found Only: "Where is the item now?" (required for found items).

Manual-First AI Tagging Behavior

  • Selecting a photo triggers asynchronous background request to Flask CV service.
  • A subtle "Detecting..." indicator appears briefly.
  • When recognized, dropdowns auto-select with "Suggested automatically. Please check."
  • If the model is slow or fails, category defaults to "other" without blocking the user.
  • On submit, valid item redirects directly to its Item Detail page.

Item Detail (Left Column)

  • Full photo, tags, date, location, and full description.
  • For found items: prominent "Where it is now" notice.
  • "Contact the poster" button: Calls /api/items/:id/reveal-contact and displays copyable phone/email + claimant reminder note.
  • "Mark as returned" button: Open confirmation dialog; archives item from active matching.

Top-3 Matches (Right Column)

  • Displays up to 3 opposite-side active items.
  • Qualification rule: Must share the same category OR at least two matching reasons.
  • Reason Chips: Plain-language chips (e.g. Same category, Same color, 2 shared keywords, Shared location word, Close date).
  • Match Tier: "Strong match", "Good match", or "Possible match".

Feed & Match Edge States

  • Seeded Items: 5 items (blue backpack, black bottle, grey phone, red umbrella + 1 returned item).
  • Empty Filter State: "No items match these filters" + "Clear filters" button.
  • No Matches State: "No matches yet. We’ll show likely matches here when someone posts a matching item. Check back later."

Technical & Lifecycle States

  • CV Service Offline: Form continues normally without errors; user selects dropdowns manually.
  • Returned Status: Detail page displays muted Returned badge; resolution notice replaces buttons.

Single-Hex Color Palette

  • Background: #f8fafc | Cards: #ffffff | Borders: #e2e8f0
  • Primary Accent: #4338ca
  • Lost Badge: Text #d97706, Bg #fef3c7
  • Found Badge: Text #0d9488, Bg #ccfbf1
  • Returned Badge: Text #6b7280, Bg #f3f4f6
  • Match Tiers: Strong #16a34a, Good #2563eb, Possible #64748b
  • Reason Chips: Text #0369a1, Bg #e0f2fe

Non-Goals Confirmed

  • No user accounts, passwords, or session tokens.
  • Open "Mark as returned": Anyone with the link can resolve an item without auth checks.
  • No live chat or socket servers.
  • No native mobile apps.

✅ Observable Acceptance Criteria

  • ✓
    Feed loads populated with 5 seeded items (4 active across bag, bottle, phone, umbrella + 1 returned).
  • ✓
    Photo upload is mandatory, images only, max ~5MB, with an immediate preview.
  • ✓
    Unrecognized photo defaults to "other" without blocking manual dropdown selection.
  • ✓
    Matching requires same category OR at least two matching reasons.
  • ✓
    Location match evaluates shared meaningful words (e.g. "Library").
  • ✓
    Contact info is hidden from the feed and shown only when someone clicks "Contact the poster".
  • ✓
    Anyone can confirm "Mark as returned", updating item status and removing it from active matching.
